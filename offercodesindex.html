Understanding OOTB vs. Custom

What Microsoft Provides vs. What You Build

What "Out-of-the-Box" Means

OOTB (Out-of-the-Box) features are capabilities that exist in Dynamics 365 immediately after installation, requiring only configuration (turning on, setting up, connecting) but NO programming, NO custom code, NO API development, and NO third-party tools. If you can do it through the Settings menu, it's OOTB.

Pre-Approved Credit Cards (OOTB)

Reservation Numbers & Pre-Screening

Critical OOTB Limitation

Dynamics 365 does NOT have OOTB credit bureau integration or soft pull capabilities. Pre-approved offers require credit data that must come from external sources (Experian, Equifax, TransUnion). However, you can manage the process and data using OOTB features once the credit data is imported.

What IS Possible OOTB (After Data Import)

Requirement OOTB Solution How It Works Data Source
Reservation number generation Marketing Coupons Create coupons with pattern PRE-[Segment]-#### D365 Generated
Pre-approved customer list Marketing List (Dynamic) Query: Credit Score > 720, No recent delinquency Imported from Bureau
Offer personalization Customer Insights - Journeys Dynamic content based on credit tier fields Contact custom fields
Response tracking Campaign Response Record when customer uses reservation number Manual entry or import
Application routing Business Process Flow Stage: Pre-approved → Application → Decision → Funded D365 workflow
Offer expiration Workflow + Field Date field with workflow to update status D365 calculated
Opt-out management Marketing List Exclusions Suppress customers who opted out of pre-screened offers Manual list or import

OOTB Data Structure for Pre-Approved Offers

Entity Marketing Coupon (standard)
Code Pattern PRE-[Month][Year]-[Segment]-[Random4]
Customer Segmentation Marketing List with query on custom "Credit Tier" field
Offer Terms Storage Coupon "Description" field or related Product
Response Method Campaign Response entity (Phone, Web, Mail)
Decision Tracking Opportunity entity with custom "Decision" field

What Requires Extension/Integration

  • Credit Bureau Soft Pull: Must purchase Experian Connect, Equifax, or TransUnion API integration (third-party or custom)
  • Real-time Credit Decision: D365 has no OOTB credit scoring engine
  • Hard Inquiry Recording: No OOTB integration with credit bureaus for hard pulls
  • Adverse Action Notice Generation: Can create document template OOTB, but auto-population requires integration
  • Firm Offer of Credit Compliance: Requires custom validation logic to ensure offer honored

Final Assessment: What You Get OOTB

Approximately 60-70% of your requirements can be met with OOTB Dynamics 365 features through configuration. This includes customer management, offer code generation, campaign orchestration, email marketing, basic tracking, and reporting.

The remaining 30-40% requires integration with core banking systems, credit bureaus, and payment processors. These are not limitations of Dynamics 365, but rather the reality that D365 is a CRM platform, not a core banking system.

Recommended Approach for Your Bank

Phase 1 (OOTB Only): Implement customer management, marketing campaigns, offer code generation, and tracking using standard features. Use manual processes or Excel imports for core banking validation.

Phase 2 (Configuration): Add custom fields for banking-specific data, create workflows for automation, build dashboards for reporting.

Phase 3 (Integration): Add Power Automate flows for core banking APIs, credit bureau integration, and automated reward processing.
